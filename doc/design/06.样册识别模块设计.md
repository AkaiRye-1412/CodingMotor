## 1. 范围与目标

一句话：**上传一个样册 PDF，得到一份 Excel；核对后可一键把 Excel 里的电机写进电机库。**

```
上传 PDF → 坐标级版面解析 → 生成 xlsx（4 类工作表）→ 下载
                                        └→ 入库（按主键覆盖/新增）→ 电机库
```

**本次改版取消的功能**（v1 有、v2 明确不做）：

| 取消项 | 说明 |
|---|---|
| 识别草稿（Draft） | 不再生成草稿对象、不再落 `job.json` 的 drafts |
| 字段映射与校验（人工） | 不再由用户逐条对齐 K2 模板 / 别名 / 单位换算；改为入库时**自动**映射，映射不上的按跳过处理 |
| 勾选提交入库 | **不再逐条勾选、逐条编辑**；第三阶段「入库」一次性处理 Excel 里的全部电机（覆盖/新增），见 §6.1 |
| 页面级解析与置信度 | 不再有 per-page 状态机与 0.6 标红 |
| 图片 / OCR | 只接受 PDF；扫描件与「参数表是位图」的页走 OCR（见 §5.4），其余图片内容不处理 |

**边界**：不触碰计算内核（K1/K3/S3/S4）；入库只经 `MotorService.create/update`（S1 唯一写库入口），
本模块自身仍不落库（产物只有 xlsx 与临时目录）。

**只抓「性能参数」**（2026-11-19 用户裁定）：样册的「性能参数 / 机械参数 / 编码器参数 / 其他信息（或「其它信息」）」几个分节里，**只保留「性能参数」**，其余分节整节丢弃。被丢弃的行数记在「识别报告」页（`分节明细`、`丢弃行数`），可追溯。口径集中在 `LayoutRules.KEEP_SECTIONS`（白名单，名单外的分节一律不进 Excel）。

**性能参数里也不采集「最高线圈温度」**（2026-11-19 用户裁定）：这一项对选型计算没有输入价值，采集清单里不需要；按 `LayoutRules.EXCLUDED_PARAM_*` 逐行剔除，报告页单列「不采集参数 / 按采集口径剔除」说明删了几行。分节过滤（整块不要）与采集过滤（个别项不要）**分开记账**，避免用户以为识别丢行。

## 3. 任务状态

| 状态 | 含义 |
|---|---|
| `READY` | 识别出至少一张参数表，xlsx 可下载 |

## 5. 解析算法（与 pdf2excel.py 一一对应）

```
PdfPageScanner   ① 取字形坐标 → 聚成视觉行 → 按间距切 run；② 取浅蓝填充块作分节行
CatalogParser    ③ 找表头 → ④ 定列边界 → ⑤ 型号/接法列归属 → ⑥ 解析表体 → ⑦ 合并与分节 → ⑧ 脚注
CatalogWorkbookWriter  ⑨ 写 4 类工作表
```

| 步骤 | 规则 | 代码 |
|---|---|---|
| ① 文字 | 取每个字形的 (x, 基线 y, 字号)。先按基线 y 聚成视觉行（容差 0.8），行内按 x 排序后按水平间距切 run（字号 × 0.33，夹在 1.0–6.0pt） | `PdfPageScanner.buildRuns` |
| ② 分节色块 | 遍历填充路径，取填充色接近 `#CCE1F5`、宽 ≥150、高 3–22、左缘 ≤90 的矩形 | `PdfPageScanner.BandScanner` |
| ③ 表头 | 同一行同时含「符号」「单位」（或「单位」+ 串联/并联）即表头；表头左侧的 token 作分节名 | `CatalogParser.headersIn` |
| ④ 列边界 | 由「符号」「单位」中心线取中点得 sym/unit 边界；**接法列 = 表头里位于「单位」右侧的所有 token**（串联/并联、L/H、A/B…，不认词表）；接法列以相邻中心线中点为界，最后一列到表右缘（表头行覆盖色块的右缘） | `buildColumns` |
| ⑤ 型号 | 表头上方一行若全是型号样式 token → 多型号对照表，按 bbox 覆盖的接法列归属；否则取上方最近的型号 token；多型号时取公共前缀 | `modelGroups` / `namesFromTitle` |
| ⑥ 表体 | 从表头下一行起，遇「行首小字号数字」或行距 >17pt 结束；每行按列中心落格，格内多行用「；」连、**紧贴正文**的小字号纯数字抽为脚注编号 | `parseBlock` / `joinCell` |
| ⑦ 合并 | 无名行按 y 就近并入有名行（≤11pt）；只有参数名的行作纵向合并标签；无符号列的行视为跨列合并 | `attachContinuations` / `mergeLabelRows` / `mergeCells` |
| ⑦′ 分节过滤 | 只保留 `LayoutRules.KEEP_SECTIONS` 里的分节（当前仅「性能参数」）。数据行本身不带分节，按 `KIND_SECTION` 行顺序维护「当前分节是否保留」，第一个分节之前的表头区默认保留。**放在行合并之后**执行，保证「分节明细 / 丢弃行数」与「参数行数」口径一致 | `keepWantedSections` |
| ⑦″ 采集过滤 | 保留的分节里再按「不采集参数」名单逐行剔除（2026-11-19 用户裁定：**不采集「最高线圈温度」**）。判定双路：符号归一后为 `tmax`，或名字含「线圈温度 / 绕组温度 / coil temp / winding temp」。**放在分节过滤之后**，删了几行单独统计进 `excludedParams`，与「丢弃行数」分开记账 | `dropExcludedParameters` / `LayoutRules.isExcludedParameter` |
| ⑧ 脚注 | 表块下方、行首 x∈[36,54) 的编号为脚注号；正文限左缘 45–58 且行距 <13 的续行拼接；遇 `Notes`/英文注记/图注词停止 | `parseFootnotes` |

### 5.1 四个必须踩过的坑（改版中定位并修正）

1. **旋转 90° 的坐标轴标注**：样册图表轴标签是竖排文字，PDFBox 的 `getYDirAdj()` 会按文字方向投影，把 `100.0` 这类轴标签"投影"进表格区域造成串数。改用 `getY()`（真实基线 y）后归位。
   > 对照：脚本版用 PyMuPDF 的 rawdict，没这个坑，所以不能直接用 `getYDirAdj()` 对齐。
   > **2026-11-19 补充**：改用 `getY()` 只解决了一半——`x0` 取的 `getXDirAdj()` 同样是「沿文字方向」的量，遇到 90° 旋转会退化成「≈基线 y」，于是标注横穿表格。ADR050-T-014（第 269 页）的「相间电阻」行因此变成 `sym=R / unit=5Ω / 值=3.300.86；.0`，整台电机入库报「缺少必填参数」。现在在 `PdfPageScanner.dropRotated` 里按 `TextPosition.getDir()` 直接丢掉旋转字形（水平字形占多数时才丢，整页横排的图纸不丢）。
2. **同字双绘**：样册常把同一行字以「填充 + 描边」画两次，PDFBox 默认去重被绕过后会出现重叠 run（"转" / "转矩" / "矩-"）。按 (字, 坐标) 自行去重。
3. **脚注编号与正文粘连**：脚本按 PyMuPDF 的 span 边界天然分开，几何切分分不开（间距只有 1pt）。按「行首单个非零数字 + 紧跟中文」还原编号。
   > **2026-11-19 补充**：符号的下标与脚注号特征完全重合（都是小字号纯数字、都紧贴前一字符）。`R25` 的 `25` 被当脚注抽走后符号只剩 `R`。判据只能落在**列**上——脚注号跟在参数名后面（名字列），下标长在符号里面（符号列），因此 `joinCell` 对 `sym` 列不抽脚注。
4. **接法列不能写死词表**：早期只把「串联/并联/单列/双列」当接法列，AKH 系列用 `L` / `H` 标列（一页三个子型号 × 两种接法 = 6 列），认不出就退化成「整表一列『值』」，数值还会被单位列吃掉（`unit=N631631`）。改为「单位右侧的 token 一律是接法列」。回归用例：`lettersRightOfUnitBecomeConfigColumns`。

### 5.2 全部数值口径集中在一处

`render/LayoutRules.java` 是唯一来源（容差、字号阈值、色块条件、脚注区间、型号正则、保留分节白名单 `KEEP_SECTIONS`）。调参只改这里，并跑 `CatalogParserTest` 回归。

### 5.3 图片型参数表检测（2026-11-19 追加）

客户图纸（如 `AKM100-B4 customer drawing`）的 `SPECIFICATION` 表是把整张表截图贴进页面的位图，文字层里只有图框与标题栏。此时「未识别到表头」的说法会误导用户以为算法坏了，必须能区分。

两个条件同时满足才判为「参数表是图片」（`ParsedCatalog.imageTablePages`）：

1. **位图占页面面积 ≥ 30%**（`IMAGE_PAGE_COVERAGE`）；
2. **页面文字里出现 `SPECIFICATION` / `规格` / `参数表` / `技术参数` / `性能参数`**（`SPEC_TITLE_PATTERN`，忽略大小写）。

面积算法：图像永远绘制在单位正方形上，所以面积 = 当前 CTM 的 2×2 行列式绝对值 `|a·d − b·c|`，累加后除以页面面积。

**为什么不用 `drawImage(pdImage)` 回调统计**：PDFBox 的默认 `Do` 处理器要先把图解码成 `PDImage` 才会回调，样册里的图是 JPEG2000，缺 JAI 解码器时整张图被跳过，覆盖率会恒为 0。改为自己注册 `Do` 操作符处理器，直接读操作符与 CTM：

- `PDImage` → 累加面积（不解码）
- `PDFormXObject` → `showForm()` 递归（Form 内的位图同样计入）

同时把 `drawImage` 覆盖为空实现，避免将来重复累加。

实测口径：客户图纸参数表页 59.0%（与 PyMuPDF `get_image_info` 完全一致）；同文件纯矢量尺寸图页 0.1%、接线图页 5.5%；真实样册 324 页中 `imageTablePages` 为空（JPX 图走另一条绘制路径，统计不到 —— 保守方向，只会漏报不会误报）。

### 5.4 位图参数表的 OCR（2026-11-19 追加）

上一节的检测只能「告知」，客户图纸里那张 1536×1495 的参数表仍然拿不到数。用户裁定接入 OCR：**位图型的参数表也要变成 Excel 数据**。

做法是「OCR 只负责把图变成文字行，版面逻辑一行不改」：

```
PDF 页 ──渲染 300dpi──▶ 位图 ──DB 检测 + CRNN 识别──▶ OcrTextLine[]
                                                  │
                                     换算成 pt 坐标的 TextRun
                                                  ▼
                            与文字层同一套 groupLines / 表头 / 列边界 / 分节 / 脚注
```

**触发条件**（`CatalogParser.isImageSpecPage`）：位图占比 ≥ 30%，且满足其一 ——
①页面文字里有 `SPECIFICATION`/`规格`/`参数表` 之类标题（「文字版图纸把表贴成图」）；
②整页几乎没有文字（纯扫描页，没有文字层可丢，OCR 是唯一出路）。
每本最多 OCR 12 页（`OCR_MAX_PAGES`），避免整本扫描册把转换拖成几分钟。

**兜底第二遍（同一天追加）**：客户图纸 `ACD85-P-15` 暴露了上面的条件不够用 ——
它的参数表同样是位图（第 2 页占 45.8%），但**整页文字里没有任何 SPECIFICATION 字样**，
标题 `Model / Symbol / Unit` 本身就画在图片里，文字层只剩标题栏套话。两个条件都不成立，整本 0 表。

于是加一条**文档级判据**：第一遍跑完后若 `tables.isEmpty()`，就认定「这多半是图纸或扫描件」，
对图片占比 ≥ `OCR_FALLBACK_COVERAGE`（0.10）的页逐页补一次 OCR。
接线图页（ACD85 第 3 页，28%）也会被拖进来跑一遍，但表头校验会挡掉，只损失几秒。

这条判据的好处是**大样册零代价**：只要有一页能解析出表，就不进兜底分支
（324 页大册子仍是 4.5s、无 OCR）。

**型号与单位的两处归一**（同批修正）：

- 接法后缀原来只认中文 `串联/并联`，客户图纸的配置列写 `Parallel`，型号就成了
  `ACD85-P-15-Parallel`。`CONFIG_SUFFIX` 补上 `series|serial|parallel`，并**锚定字符串末尾**
  （配置名就是整个接法词，所以 `Parallel Shaft` 这类词组不会被误缩写）。
  注意不能用 `\b` —— Java 的 `\b` 基于 ASCII 的 `\w`，跟在中文后面永远不成立。
- 「无单位」在样册里写作 `-`，OCR 极容易读成汉字「一」（笔画相同），Excel 里会出现
  `Pole Number | 2p | 一 | 8`。`normalizeUnit()` 把整格只有一个横线类字符的单位统一成 `-`。

**模型与运行时**：PP-OCRv6 small（det + rec）+ ONNX Runtime Java，全离线，模型随 jar 打包在 `resources/ocr/`。

| 项 | 取值 | 理由 |
|---|---|---|
| 渲染 DPI | 300（`OCR_DPI`） | 1600px 上限的旧值会让 8pt 表格字只剩 13px，直接碎成单字 |
| det 输入上限 | 长边 2560 | 同上 |
| 二值化阈值 | 0.3 | DB 概率图经验值，低了对表格线敏感 |
| 水平膨胀 | 6px | 等价 DB 的 unclip：不做的话检测框只框住单个字符 |
| rec 输入高 | 48 | PP-OCRv6 训练口径 |
| CTC 字典 | 18710 类 = 1 blank + 18708 字符 + 1 空格 | `index 0 = blank`，输出取 `charset[best]` 而非 `best-1` |
| 最小字高 | 10px | 更小的框基本都是表格线/噪点，识别只会产乱码 |

**三个必须记住的坑**：

1. **字典不能用 `getCustomMetadata()` 读**。ONNX Runtime Java 按平台编码（Windows 上是 GBK）解码元数据字符串，中文全变 `?`、换行数从 18707 掉到 18165，解码整体错位。改为 Python 侧导出 UTF-8 的 `charset.txt` 打包进 resources。
2. **基线要取文字框中心，不能取底边**。`Symbol` 与 `Unit` 的底边因下伸部差 2px，超过 `BASELINE_TOLERANCE` 后表头被拆成两行，`headersIn` 直接返回空。
3. **裁剪必须整体平移**：`g.drawImage(src, -x0, -y0, null)`。最初写成 `max(0, pad - (x - x0))`，结果裁出来的永远是原图左上角，识别全乱码。

**版面适配**（只在 OCR 页生效，不影响文字层样册）：

- 行距上限 `BLOCK_LINE_GAP_OCR = 26.0`（图纸行距约 18pt，文字层用的 17 会把第一行就断掉）。
- 表格右边界：OCR 页常常没有底色块可依，用表头列距中位数推出「下一列」位置（`columnStep`），否则最右一列数值被裁掉。
- 单位列与值列的切分：单位右缘与值列左缘的中点（`tightUnitColumn`）。文字层样册若用这条会把型号分组切坏，故仅 OCR 页启用。

**耗时**：客户图纸第 2 页 3 页文档整本 3.3s（含 OCR 模型首次加载约 1s，识别 243 行）。

### 5.5 文本归一与写盘健壮性（2026-11-19 追加）

**原则**：**版式不同不是错误**。客户图纸有无数种排法（单列 `Value`、无接法列、表头在图片里、型号带 `/`），
任何一处「数据形状」都不该让整次转换失败——用户拿不到 Excel，比拿到一份有小瑕疵的 Excel 糟糕得多。

**解析侧归一**（`CatalogParser`）：

| 输入形态 | 归一处理 | 理由 |
|---|---|---|
| 参数名夹脚注标记 `@100C[1]`、`±20%[³]`、`Max. Speed⁴` | 剥出编号进「脚注」列，名字还原干净 | 带标记的参数名永远匹配不上字段字典 |
| 小字号参数值（`持续推力 28`、`电磁周期 60`、`磁吸力 0`） | 值列保留。脚注号的判据是「小字号 + 1~2 位数字 + **紧贴前一段正文**（≤3pt）」，数值单元格只有它自己一个 run，不会被误判 | AUM3 参数表用 5pt 排数值，旧的「小字号 + 1~2 位」判据把 28/60/0 当成脚注号抽进 footnote，值列变空 → Excel 里整行没有持续推力 → 入库报「缺少必填参数：持续推力」（2026-11-19 修正，`FOOTNOTE_ATTACH_GAP`） |
| 符号下标（`R25`、`Kthn`、`Ubus`） | 符号列**不抽脚注**，`R25` 完整保留 | 下标与脚注号特征完全重合（小字号纯数字紧贴）。ADR050-T-014 的 `R25` 被剥成 `R` → 该行匹配不上「相间电阻」→ 入库报缺必填（2026-11-19 修正） |
| 旋转 90° 的图纸标注 | 按 `TextPosition.getDir()` 整段丢弃（仅当该页水平字形占多数） | `getXDirAdj()` 在旋转文字上退化成「≈基线 y」，标注横穿表格 → 单位变 `5Ω`、值变 `3.300.86；.0`（ADR050-T-014 第 269 页，2026-11-19 修正） |
| 整格只剩标记 `[1]` | 名字置 `（未识别）` | 留空会被续行逻辑当成上一行的续行，把独立参数的值粘到邻行（`Te 6.90` 变成 `6.90；6.0`） |
| 「有名无值」+「无名有值」两行（OCR 把名字与数值排到两条基线） | 按纵向就近（≤ `CONTINUATION_ATTACH`）拼回一行 | 图纸里 `Continuous Current = 6.0` 曾整行丢值 |
| 拼不上的无名行、值只有 `—` | 丢弃 | 整行无信息，留着只会污染表 |
| 型号带版次词 `CRM0013-Preliminary` | 去掉版次词 → `CRM0013` | `Preliminary / Draft / 初步` 是「本表为初版」的标注，不是型号 |
| 单位列是 `一` / `■` / `－`（`-` 的退化解） | 统一成 `-` | OCR 把横线读成汉字「一」或方块 |
| 度数符号 `℃`、`°℃` | 统一成 `°C` | 同一列三种写法看着像三个不同单位 |

**写盘侧防御**（`CatalogWorkbookWriter`）：

| 风险 | 处理 |
|---|---|
| `addMergedRegion` 单格区间 → POI 抛 `Merged region D9 must contain 2 or more cells` | 统一走 `merge()`：区间不足两格直接跳过。**单列 `Value` 表**里「串联/并联共用一格」本来就没有第二格可合 |
| 型号含 `/`（`AKM100-B4/D79`）→ POI 抛 `Sheet name ... is invalid` | `sanitizeSheetName()` 清 `[ ] : * ? / \`、限 31 字、重名加后缀 |
| 两列同名 → `Set.copyOf(labels)` 抛重复元素 | 改用 `stream().allMatch()` 判断 |
| 兜底列名 `Value / Values / Typical / 值 / 列N / vN` | 不拼进型号（否则出现 `CRM0013-Value`、`CLA0010-025-Values`） |

### 5.6 列归属与「同一行被拆成多条基线」的还原（2026-11-19 追加）

OCR 的检测框和表格线不可能严丝合缝，于是出现两类系统性错误。它们不是「识别不准」，
而是**版式解读口径不对**，因此都在算法层统一解决，不逐个 PDF 打补丁。

**① 列归属：看左缘，不看中心线**

原来按文字中心点 `cx()` 判列。表格里文字从列左边界开始写，左缘永远在自己的格子里，
而中心点在字很宽时会越界：

| 实例 | 左缘 | 中心 | 正确列 | 按中心判的结果 |
|---|---|---|---|---|
| `Vpeak/(m/s)`（AKM200） | 403.0（单位列 370.5–425.9） | 429.8 → 值列 | 单位 | 单位丢失，值变成 `Vpeak/(m/s)356` |
| `N/Sqrt(W)` | 402.0 | 429.8 → 值列 | 单位 | 同上 |

改为 `Columns.of(run)`：**按左缘归列**。但左缘要留两个修正，否则反向出错：

- **检测框左偏**：符号 `Fcn` 的左缘 490.1 落进参数名列最后 0.6pt（列边界 490.7）。
  规则：左缘贴近本列右边界（`COLUMN_EDGE_TOLERANCE = 6pt`）时再看一眼，
  **只有文字主体一半以上已经在下一列**才归下一列。
- **右对齐的短值**：`磁吸力` 的 `0` 左缘 205.0 距 v0 右界 210.1 只有 5.1pt，
  但一点没越界——上面那条第二判据会拦住（越界部分为 0），仍归 v0。
  早期只加「贴边就跳列」导致 5 行 `0.0` 变成 `00`，就是漏了这个判据。

回归用例：`ColumnAssignmentTest` 前 3 项（宽单位 / 右对齐短值 / 左偏符号）。

**② 同一物理行被拆成多条基线**

符号字身矮，OCR 常把它单独切到另一条基线，`groupLines` 的 `LINE_TOLERANCE` 收不住：

```
名字/单位/值   oy=319.1   Electrical Time Constant | | ms | 0.35
符号           oy=321.5   | Te |  |
```

旧逻辑把这种「无名行」按 `r.sym + r.unit + values` 拼成字符串挂到最近的有名行，
结果单位格变成 `ms0.35；Te`——整行作废。现在按顺序处理：

1. **补空列**（`attachContinuations`）：无名行的符号/单位/值，若目标行对应格是空的就直接填进去，
   而不是拼成字符串。符号格非空时取**更长**的那个（`1` 是 OCR 把 `Icn` 切开的碎片）。
2. **平分时归上方**（`CONTINUATION_TIE = 3pt`）：名字跨两行、值居中时，两截名字与值的距离几乎相等；
   参数名的第一行才是这行参数的锚点。
3. **名字续行合并**（`mergeWrappedNames`）：只剩名字、符号/单位/值全空的行，若名字以
   `(`、`@`、`[`、数字或小写字母开头，且与相邻有值行距离 ≤ 1.6 倍行距，就接回上一行名字。
   三条同时成立才合并——独立参数行不可能三列全空，分节行已被 `markSections` 标成 section 而排除。

效果：`Electrical Time Constant | Te | ms | 0.35`、`Continuous Current | Icn | Arms | 2.0`、
`Magnetic Period | TNN | mm | 24`、`Continuous Power Dissipation (NC @100C | Pcn | W | 40.2` 全部还原。

**③ 多值拼接不再吞掉单位**：`attachContinuations` 拼多值时 `base = 单位 + 值`，
旧实现直接把 `target.unit` 清空，单位被搅进值里（`N/Sqrt(W)12.0`）。
现在若值确实以单位开头就剥掉重复前缀、单位留在单位列；只有单位来自别的行时才退回整串入值。

**回归基线**（真样册必须零变化）：

| 文件 | 结果 |
|---|---|
| AXD-ERA 样册 | 5 表 / 170 数据行，与改动前**逐行完全一致** |
| Direct Drive（324 页） | 177 表 / 6420 数据行（改动前 6419；差异集中在第 196、269 页——这两页是双表并排的异常版式，旧版同样有杂质，只是位置不同） |
| 4 份客户图纸 | 行数与逐格值均不变 |

### 6.1 入库（I6）口径

**数据源是 Excel，不是内存里的解析结果**：用户核对的就是这份 xlsx，两者不一致时以 xlsx 为准。
读取时用 `DataFormatter` 取「看到的那串字符」，避免 `3.4` 变成 `3.4000000000000004`。

```
result.xlsx ──读「参数汇总」6 列──▶ 行 ──定类型/取字段/拆主键──▶ 一台电机 ──覆盖或新增──▶ 电机库
```

| 环节 | 规则 | 代码 |
|---|---|---|
| 范围 | **只处理当前任务**（路径里的 `{jobId}` 这一份 xlsx），不扫历史任务——按钮语义与用户正在看的表一致，重复点也不会误伤别的任务；要入库别的任务先打开它 | `ImportController.commit` |
| 读表 | 固定 6 列；空型号行跳过；值列数字格/文本格一视同仁 | `CatalogSummarySheet.read` |
| 定类型 | 每一行去三套模板里试着匹配字段，**命中数最多者胜**（并列按 A1 顺序）；力矩的 `Tcn/Tpk/Kt/2p/Ωmax`、音圈的 `行程` 天然区分 | `CatalogRowMapper.detectType` |
| 取字段 | **符号优先**（`R25` 比「相间电阻 @25°C ±10%」稳）；符号重复（力矩两行都写 `Ωmax`）或缺失时退回参数名：①精确 → ②去掉 `@100°C`/`±10%` 后精确 → ③唯一「包含」；**候选不唯一即视为不确定，该行不取值**（宁可跳过，不猜）。两条例外：①**冷却尾字母**——`Kthw`/`Icw`/`Pcw`（水冷）、`Ktha`/`Ica`/`Pca`（气冷）去掉尾字母再比，还补一个自冷收尾 `n`（`Icw → Ic → Icn`）；②**短别名必须落在词边界上**——`Ip` 不许命中 `dissi**p**ation`、`Ic` 不许命中 `magnet**ic**`（详见 §9） | `resolveField` / `byCoolingSuffixSymbol` / `containsLoose` |
| 数值 | 取首个数值串（`<0.5`→0.5、`1,700`→1700、`-`→非数值丢弃）；录音圈质量时按 K2 `factor` 由 `g` 换算 `kg`，样册直接给 `kg` 则不再乘 | `parseNumber` / `scaleOf` |
| 主键 | **型号名原样取「参数汇总」的型号列**（第 65 轮裁定）：`AXD120-71-S` 入库仍是 `AXD120-71-S`，配置名恒为 `默认`；**不再**把 `-S`/`-P` 拆回「串联/并联」 | `keyOf` |
| 门槛 | 必填 = K2 `requiredKeys`；缺任何一项即**跳过**并列缺项，不补 0、不猜值 | `CatalogCommitService.commitOne` |
| 写入 | 主键已存在 → `update`（**整体替换**，非字段级合并）；不存在 → `create`。逐台独立事务，一台失败不影响其他台 | 同上 |
| 元数据 | `entryMethod=识别草稿`、`enteredOn=今天`、`sourceDoc=PDF 文件名`、`note=样册识别入库（任务 xxx）`；`sourcePage` 留空（Excel 未保留页码） | 同上 |
| 结果回传 | 逐台带回 `spec`（K2 字段 key → **内部单位**值）：已认出来的参数，供前端「补全参数」预填；缺的必填项自然不在这里 | `ImportCommitItem.spec` |
| 补全并入库 | 被跳过的电机可在结果页点「补全参数」→ 打开电机库录入表单（预填 `spec`，按 K2 `factor` 反算回录入单位）→ 补齐保存即 `POST /api/motors` 写这一台；撞上同名主键自动转 `PUT` 覆盖。**不重跑整批**（避免覆盖用户手工改过的电机），结果页该行就地改为「新增/覆盖」并调整计数 | `MotorEntryDialog`（prefill）/ `ImportDialog.openFix` |

**结构与冷却**：结构样册/图纸不给，按 K2 模板首项兜底 —— 直线 `无铁芯`、力矩 `有铁芯`、音圈 `音圈`。
**冷却方式跟数据走**（2026-11-19 第二次细化）：①先在**参数表**里找证据——参数名带「气冷/水冷」以及英文写法 `(AC)` / `(WC)`
（`WC = Water Cooling`，用户确认；`AC = Air Cooling`）；②没有中文/英文标注时，看**型号结尾**的 `-A` / `-W`
（`MotorCooling.bySuffix`，只看结尾、**不看中间段**：`AKM200-A-B4` 的 `-A-` 是「A 型」结构代号，不是气冷）；
③都没有才取模板首项 `普通`。模板里没有该选项时（音圈只有「普通」）退回首项，绝不写非法值（库表 `CK_MOTOR_COOLING`）。
结果页逐台回显这两列，用户可在电机库中按实物修改；**不做静默猜测**（如从型号猜铁芯/无铁芯）。

**为什么不做字段级合并**：样册是「同一型号的权威数据」，半新半旧比整体覆盖更难排查。用户原话：
「如果库里有的，那么重新覆盖直接替换之前的」。代价是手工补过的中孔/厂商会被清空，因此结果页明确写出覆盖语义。

### 7.1 冷却变体拆分（2026-11-19 用户裁定）

样册把一款电机的参数按冷却方式并排列出时（`AUM4-S1-S` 的持续电流、持续热功率、热耗散常数各有自冷/气冷/水冷三条），
**按冷却方式拆成独立型号**——否则下游分不清三条持续电流各对应哪种冷却，入库还会因「同一字段重复出现」只留下第一条。

| 参数名里的标注 | 输出型号 | 收哪些行 |
|---|---|---|
| 自冷（或完全不带标注） | `AUM4-S1-S`（原名不变） | 带「自冷」的行 + 不带冷却标注的行 |
| 气冷 / 风冷 / 空冷 / `Air cooled` | `AUM4-S1-S-A` | 带「气冷」的行 + 不带标注的行 |
| 水冷 / 液冷 / `Water cooled` | `AUM4-S1-S-W` | 带「水冷」的行 + 不带标注的行 |

四条口径：

1. **后缀拼在最后**：接法后缀（`串联 → -S`）先拼、冷却后缀后拼 → `AUM4-S1-S-A`（不是 `AUM4-S1-A-S`）。
2. **参数名不改**：`持续电流（水冷）@100℃` 原样保留，与样册逐字对得上；三张表靠型号名区分。
3. **通用参数三个型号共用**；某型号缺某项（只有气冷值、没有水冷值）就**留空**，不借用其他冷却的值。
4. **没有自冷数据就不出基型**：AKM/AKH 的 `-W` 系列只给水冷值，出基型只会多一台缺「持续电流/持续推力」的残型号；
   型号里已经带独立的 `-W-` / `-A-` 段时（`AKM100-W-B2-S`）不再追加同样的后缀。
5. **样册里没有值就不新增型号**（同日第二次裁定）：一张表并排列着十几个型号时，常有几列只给了自冷值、
   气冷/水冷那几行写的是 `-`（AUM5 的 P5 列就是）。这种列若跟着变体表一起输出，就会生成
   `AUM5-S1-P5-A` 这类缺「持续推力/持续电流」的残型号，导入时只能「跳过」。
   因此变体按<b>列</b>判定：本变体在所有列上都没有实值 → 整张变体表不生成；只在部分列有值 → 只投影这些列
   （值列键重新编号，避免串列）。判据只看<b>本变体的行</b>——「峰值电流」这类通用行有值不算「这个型号有气冷」。
   实测 324 页样册：`AUM5-S1-P5-A` / `-P5-W` 不再出现，`-P-A` / `-S-W` 保持 15 行满参数，长表数据行 6575 → 6545。

拆出来的型号在「参数汇总」「每型号一页」里各占一份，**入库也是各自一台电机**；冷却字段按该型号数据行里的标注自动填
（`-A → 气冷`、`-W → 水冷`、基型 → `普通`）。报告页的「冷却变体口径 / 冷却变体」两行说明本次拆了哪些型号。

口径实现集中在 `CoolingVariants`（识别英文/中文同义词、判变体、拼后缀），写盘时就地拆表，解析结果不改。

格式约定：表头深蓝 `#1F3864` 白字；分节 `#D9E2F3`；边框 `#BFBFBF`；**数值按原字符串小数位设格式**（`10.0`→`0.0`、`1.18E-03`→`0.00E+00`），文本单元格用 `@`；超 15 位或带前导零的数字按文本保留。

   与「下载 Excel」。失败（如任务已清理）退回第 2 步并保留现场。
   **跳过/失败的行右侧有「补全参数」**：点开就是电机库的录入表单，样册已识别的值全部预填，
   缺的必填项为空并标星，补齐保存即只写这一台（不会重跑整批）；保存成功后该行就地变成「新增/覆盖」，
   横幅的「跳过 / 新增」计数同步变化。

## 9. 已知边界

| 场景 | 行为 |
|---|---|
| 扫描件 / 纯图片 PDF | 每页位图占比 ≥ 30% 且几乎无文字 → 走 OCR；OCR 出表则正常产出（`ocrPages` 标注页码）；OCR 也提不出参数行 → `EMPTY`，提示「已尝试 OCR 但没能提取出参数行」 |
| **参数表以位图嵌入**（客户图纸常见） | 两条路径：①页面有 `SPECIFICATION`/`规格` 标题 → 当场 OCR；②整本一张表都没解析出来 → 对图片占比 ≥10% 的页兜底 OCR（应对「标题本身在图片里」的图纸，如 ACD85）。成功进 `ocrPages`，失败才进 `imageTablePages` |
| OCR 的准确率边界 | 字符级可能误判（`0`/`O`、`1`/`l`/`I`、`°`/`o`、小数点丢失）；参数名里的脚注上标（`[1]`、`²`）常被读成 `1`、`l`、`?`。**数值列实测可靠**，名称列需人工扫一眼 |
| OCR 漏字符 | 只做**等价字形归一**（`℃`/`°℃` → `°C`、`■` → `-`），不补丢掉的字符：`@100C`（丢 `°`）、`(NC`（丢 `)`）保持原样。补字是「猜」，比留瑕疵更难发现 |
| 参数名整格丢失 | 名字位置只剩脚注标记时，该行以 `（未识别）` 占位保留数值（图纸里 `Continuous Current 6.0` 就是这种），用户可对照原图补名 |
| 旋转 90° 的参数表 | 不做旋转矫正，OCR 会按横排去读 → 识别失败，落到「未识别页」 |
| 普通图纸页（尺寸图/接线图） | 位图占比低、或没有规格标题、且有正常文字 → 只计入「未识别页」，不误报成「图片型参数表」，也不会白跑 OCR |
| 无「符号 + 单位」表头的表格 | 不识别（宁可漏，不猜） |
| 不采集的参数（当前：最高线圈温度） | 保留分节里按名单剔除：符号为 `tmax` 或名字含「线圈温度/绕组温度/coil temp/winding temp」。名单在 `LayoutRules.EXCLUDED_PARAM_*`，改名单即改口径；报告里写明「哪个参数删了几行」，不会与「丢弃行数」混在一起 |
| 不采集「最高线圈温度」的副作用 | 由样册入库的电机 `t_max` 缺值，而 `AppliedCalculator` 用它算热态电阻 `rHot` 与允许电流 `iAllow`。**口径：缺省 100 °C**（2026-11-19 用户裁定）——入库时 `CatalogRowMapper` 补 100 并在 notes 留痕，计算时 `AppliedCalculator` 再兜一层（常量 `MotorCatalogTemplates.DEFAULT_MAX_COIL_TEMP`），电机库里已有的旧数据（`t_max` 为空）也因此照常做热校核。注意**线圈温度的迭代只依赖 R25 / Kth / 实际电流**，不依赖 `Tmax`；`Tmax` 只决定「允许电流」与是否超温 |
| 型号 > 12 个 | 只出参数汇总，不出每型号页（避免上百个可分页） |
| 页面旋转 ≠ 0 | 未处理旋转页（样册通常为 0/180；如有需要按 `PDPage.getRotation()` 校正） |
| 相邻单元格间距 < 1.7pt | 可能并成一格（几何切分的固有极限，脚本版靠 PDF 文本对象边界更稳） |
| 入库：必填不全 | 该台**跳过**并列缺哪几项，不写库、不补 0；补齐样册/Excel 后可再点一次「入库」 |
| 入库：参数名/符号都对不上 | 该行不取值（`notes` 里记「未映射的参数：…」），若因此缺必填 → 跳过 |
| 入库：结构 | 样册不提供，按模板首项兜底（直线 `无铁芯`、力矩 `有铁芯`、音圈 `音圈`），需人工在电机库改 |
| 入库：冷却方式 | ①参数表证据（「气冷/水冷」及 `(AC)`/`(WC)`）→ ②型号结尾 `-A`/`-W` → ③模板首项 `普通`；模板无该选项时退回首项。中间段 `-A-` **不**当冷却证据（结构代号） |
| 入库：符号带冷却尾字母 | `Kthw`/`Icw`/`Pcw`（水冷）、`Ktha`/`Ica`/`Pca`（气冷）去尾字母后按 `Kth`/`Ic`→`Icn`/`Pc`→`Pcn` 匹配。不处理时 `Kthw` 对不上 `Kth` → 该行丢弃 → 一台参数齐全的水冷电机报「缺少必填参数：热耗散常数」被跳过（AKM200-A-B4-W-B，2026-11-19） |
| 入库：短别名撞词中段 | 长度 ≤3 的 ASCII 别名（`Ip`/`Ic`/`Pc`…）只认词边界：`Ip` 不许命中 `dissi**p**ation`、`Ic` 不许命中 `magnet**ic**`。否则「Thermal Dissipation Constant」同时命中 `kth` 与 `iPeak`、「Magnetic Period」命中 `iCont`，`unique()` 判不确定返回 `null`，两行一起消失（同上）。长度 ≥4 的别名仍按包含（`thermal dissipation` 要能命中 `thermal dissipation constant`） |
| 入库：最高线圈温度 | 样册不采集（§5 ⑦″）→ 缺值补 **100 °C**（`MotorCatalogTemplates.DEFAULT_MAX_COIL_TEMP`），`notes` 记「样册未提供最高线圈温度，按默认 100 °C 入库」。补值而非留空：库、报告、界面三处看到的才是同一个数 |
| 冷却变体：参数名不带标注 | 只有参数名里出现「自冷/气冷/水冷」（含同义词与英文）才拆；冷却方式写在**表头**（列名是「自冷/气冷/水冷」）的表不拆，按原样一表多列输出 |
| 冷却变体：缺自冷数据 | 不出基型（只出 `-A`/`-W` 型号），避免多一台缺「持续电流/持续推力」的残型号 |
| 冷却变体：型号已带冷却段 | `AKM100-W-B2-S` 这类已含独立 `-W-` 段的型号不再追加 `-W`（否则变成 `AKM100-W-B2-S-W`） |
| 冷却变体：该列没有该冷却的值 | 气冷/水冷行写成 `-` 的列视为「这个型号不做那种冷却」，**不生成变体型号**（按列判定，见 §7.1 第 5 条） |
| 入库：主键同名 | 整体覆盖（`update` 语义），手工补过的中孔/厂商/系列会被清空——这是「直接替换」的既定代价 |
| 入库：类型冲突 | 库里同名电机是直线、Excel 判成力矩 → `MOTOR_TYPE_MISMATCH`，该台计入「失败」（不允许改类型，04 C4） |
| 入库：型号本身以 `-S`/`-P` 结尾 | **不再拆分**（第 65 轮裁定：型号名以 Excel 为准，逐字入库）；代价是同一机座的串联/并联成为两个独立型号，配置名都是 `默认` |

## 11. 打包体积

OCR 的代价是体积，落点只有两处：

| 组成 | 大小 | 处理 |
|---|---|---|
| PP-OCRv6 det + rec 模型 + 字典 | 30 MB | 无解，就是模型本身（`resources/ocr/`） |
| `onnxruntime` jar | 89 MB（解开 290 MB） | **打包时裁掉**：`packaging/windows/jar_slim.py` 只留 `win-x64/*.dll`，剔掉 linux/osx 全部原生库与所有 `.pdb`/`.dSYM` 调试符号（仅 `onnxruntime.pdb` 一个就占压缩后 58 MB） |

fat jar 181.8 MB → 瘦身 97.5 MB（省 84.3 MB）。瘦身只作用于 jpackage 的输入，`target/` 里的原 jar 不动，其他平台仍可构建。
