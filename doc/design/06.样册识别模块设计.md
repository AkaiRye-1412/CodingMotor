## 1. 范围与目标

一句话：**上传一个样册 PDF，得到一份 Excel。**

```
上传 PDF → 坐标级版面解析 → 生成 xlsx（4 类工作表）→ 下载
```

**本次改版取消的功能**（v1 有、v2 明确不做）：

| 取消项 | 说明 |
|---|---|
| 识别草稿（Draft） | 不再生成草稿对象、不再落 `job.json` 的 drafts |
| 字段映射与校验 | 不再对齐 K2 模板 / 别名 / 单位换算 / `MotorSpecValidator` |
| 勾选提交入库 | **不再写电机库**；电机库仍由通道 1 手工录入维护 |
| 页面级解析与置信度 | 不再有 per-page 状态机与 0.6 标红 |
| 图片 / OCR | 只接受 PDF；扫描件（无文字层）直接判定并提示 |

**边界**：不触碰计算内核（K1/K3/S3/S4）与电机库（S1）；本模块的产物只有 xlsx 与临时目录。

**只抓「性能参数」**（2026-11-19 用户裁定）：样册的「性能参数 / 机械参数 / 编码器参数 / 其他信息（或「其它信息」）」几个分节里，**只保留「性能参数」**，其余分节整节丢弃。被丢弃的行数记在「识别报告」页（`分节明细`、`丢弃行数`），可追溯。口径集中在 `LayoutRules.KEEP_SECTIONS`（白名单，名单外的分节一律不进 Excel）。

## 2. 存储与生命周期

| 项 | 规则 |
|---|---|
| 位置 | `%APPDATA%\MotorSizer\imports\{jobId}\`（与库文件同处，A-5） |
| 内容 | `source\f1.pdf`（原件）、`job.json`（任务与统计）、`result.xlsx`（交付物） |
| 数据库 | **不落库**，全部文件系统 |
| 清理 | 启动时惰性清理 30 天前的任务目录（`ImportCleanup`）；测试用 `motorsizer.imports.dir` 指向临时目录时跳过 |

一次上传 = 一个任务 = 一个 xlsx（v2 只接受单文件，与脚本版一致）。

## 3. 任务状态

| 状态 | 含义 |
|---|---|
| `READY` | 识别出至少一张参数表，xlsx 可下载 |
| `EMPTY` | 无文字层（扫描件）或整本没识别到参数表；xlsx 仍生成，含识别报告页说明原因 |
| `FAILED` | 解析/写盘异常（正常路径下接口直接报 5xx，保留该值供磁盘历史任务自洽） |

## 4. 数据结构（job.json）

```jsonc
{
  "jobId": "imp-20261119-031500-1234",
  "status": "READY",
  "createdAt": "2026-11-19T03:15:00Z",
  "files": [{ "fileId": "f1", "name": "AXD-ERA.pdf", "kind": "pdf", "pages": 10, "sizeBytes": 1029191 }],
  "stats": {
    "pageCount": 10, "charCount": 11891, "hasTextLayer": true,
    "parsedPages": 5, "tableCount": 5, "modelCount": 5,
    "parameterRows": 222, "dataRows": 190, "footnoteCount": 7,
    "skippedPages": [1, 2, 8, 9, 10],
    "excelName": "AXD-ERA Series (CN)-23.7.1_参数表.xlsx",
    "message": "识别 5 张参数表 / 5 个型号 / 222 条参数行 / 7 条脚注；5 页未识别"
  }

```

`stats` 是前端结果页的唯一数据来源；`skippedPages` 让用户知道哪几页没被当成参数表。

## 5. 解析算法（与 pdf2excel.py 一一对应）

```
PdfPageScanner   ① 取字形坐标 → 聚成视觉行 → 按间距切 run；② 取浅蓝填充块作分节行
CatalogParser    ③ 找表头 → ④ 定列边界 → ⑤ 型号/接法列归属 → ⑥ 解析表体 → ⑦ 合并与分节 → ⑧ 脚注
CatalogWorkbookWriter  ⑨ 写 4 类工作表
```

| 步骤 | 规则 | 代码 |
|---|---|---|
| ① 文字 | 取每个字形的 (x, 基线 y, 字号)。先按基线 y 聚成视觉行（容差 0.8），行内按 x 排序后按水平间距切 run（字号 × 0.33，夹在 1.0–6.0pt） | `PdfPageScanner.buildRuns` |
| ② 分节色块 | 遍历填充路径，取填充色接近 `#CCE1F5`、宽 ≥150、高 3–22、左缘 ≤90 的矩形 | `PdfPageScanner.BandScanner` |
| ③ 表头 | 同一行同时含「符号」「单位」（或「单位」+ 串联/并联）即表头；表头左侧的 token 作分节名 | `CatalogParser.headersIn` |
| ④ 列边界 | 由「符号」「单位」中心线取中点得 sym/unit 边界；**接法列 = 表头里位于「单位」右侧的所有 token**（串联/并联、L/H、A/B…，不认词表）；接法列以相邻中心线中点为界，最后一列到表右缘（表头行覆盖色块的右缘） | `buildColumns` |
| ⑤ 型号 | 表头上方一行若全是型号样式 token → 多型号对照表，按 bbox 覆盖的接法列归属；否则取上方最近的型号 token；多型号时取公共前缀 | `modelGroups` / `namesFromTitle` |
| ⑥ 表体 | 从表头下一行起，遇「行首小字号数字」或行距 >17pt 结束；每行按列中心落格，格内多行用「；」连、小字号纯数字抽为脚注编号 | `parseBlock` / `joinCell` |
| ⑦ 合并 | 无名行按 y 就近并入有名行（≤11pt）；只有参数名的行作纵向合并标签；无符号列的行视为跨列合并 | `attachContinuations` / `mergeLabelRows` / `mergeCells` |
| ⑦′ 分节过滤 | 只保留 `LayoutRules.KEEP_SECTIONS` 里的分节（当前仅「性能参数」）。数据行本身不带分节，按 `KIND_SECTION` 行顺序维护「当前分节是否保留」，第一个分节之前的表头区默认保留。**放在行合并之后**执行，保证「分节明细 / 丢弃行数」与「参数行数」口径一致 | `keepWantedSections` |
| ⑧ 脚注 | 表块下方、行首 x∈[36,54) 的编号为脚注号；正文限左缘 45–58 且行距 <13 的续行拼接；遇 `Notes`/英文注记/图注词停止 | `parseFootnotes` |

### 5.1 四个必须踩过的坑（改版中定位并修正）

1. **旋转 90° 的坐标轴标注**：样册图表轴标签是竖排文字，PDFBox 的 `getYDirAdj()` 会按文字方向投影，把 `100.0` 这类轴标签"投影"进表格区域造成串数。改用 `getY()`（真实基线 y）后归位。
   > 对照：脚本版用 PyMuPDF 的 rawdict，没这个坑，所以不能直接用 `getYDirAdj()` 对齐。
2. **同字双绘**：样册常把同一行字以「填充 + 描边」画两次，PDFBox 默认去重被绕过后会出现重叠 run（"转" / "转矩" / "矩-"）。按 (字, 坐标) 自行去重。
3. **脚注编号与正文粘连**：脚本按 PyMuPDF 的 span 边界天然分开，几何切分分不开（间距只有 1pt）。按「行首单个非零数字 + 紧跟中文」还原编号。
4. **接法列不能写死词表**：早期只把「串联/并联/单列/双列」当接法列，AKH 系列用 `L` / `H` 标列（一页三个子型号 × 两种接法 = 6 列），认不出就退化成「整表一列『值』」，数值还会被单位列吃掉（`unit=N631631`）。改为「单位右侧的 token 一律是接法列」。回归用例：`lettersRightOfUnitBecomeConfigColumns`。

### 5.2 全部数值口径集中在一处

`render/LayoutRules.java` 是唯一来源（容差、字号阈值、色块条件、脚注区间、型号正则、保留分节白名单 `KEEP_SECTIONS`）。调参只改这里，并跑 `CatalogParserTest` 回归。

## 6. 接口（I1–I5）

统一信封 `{code, message, data}`；错误码前缀 `IMPORT_`。

| # | 方法与路径 | 职责 |
|---|---|---|
| I1 | `POST /api/imports`（multipart，字段名 `file`） | 上传 PDF，**同步**解析并生成 xlsx，返回任务与统计；非 PDF / 空文件 → 400 |
| I2 | `GET /api/imports` | 任务列表（摘要：文件名/状态/页数/表数/型号数/剩余天数） |
| I3 | `GET /api/imports/{jobId}` | 任务详情（含 stats） |
| I4 | `DELETE /api/imports/{jobId}` | 删除任务目录（原件 + 产物） |
| I5 | `GET /api/imports/{jobId}/export` | 下载 xlsx（`Content-Disposition` 带 UTF-8 文件名） |

| 错误码 | HTTP | 含义 |
|---|---|---|
| `IMPORT_JOB_NOT_FOUND` | 404 | 任务不存在 / 已清理 / 产物缺失 |
| `IMPORT_FILE_REJECTED` | 400 | 非 PDF、空文件、缺字段 |
| `IMPORT_CONVERT_FAILED` | 500 | 解析或写盘异常 |

## 7. Excel 输出规格

| 工作表 | 内容 |
|---|---|
| 参数汇总 | **固定 6 列（采集用）**：型号 / 类别（分节） / 参数名 / 符号 / 单位 / 值。**不采集脚注与页码**（脚注单独见「脚注说明」页）。**接法不单独成列**，而是并进「型号」：型号名 = 原型号 + 接法（**串联 → `-S`、并联 → `-P`**），同一参数按接法各占一行。原表是「串联 \| 并联」两列的（如 AXD-ERA）→ `AXD120-71-S` / `AXD120-71-P` 两行；原表是配置列（如 `AUM2-S2串联`）→ `AUM2-S2-S`。配置名已含型号前缀时去重（`AUM1` + `AUM1-S1串联` → `AUM1-S1-S`），不相干时中文直连、ASCII 用 `-` 连接；空值不出行，原表串联/并联共用一格（合并单元格）的行两接法各出一行同值。**只含「性能参数」行**，其余分节已过滤 |
| 每型号一页 | 型号 ≤12 个时，每个型号一张原版式表（参数名/符号/单位/接法…/脚注），分节行浅蓝合并行。同样只含「性能参数」 |
| 脚注说明 | 编号 + 说明，自动换行。脚注按整页收集，性能参数引用到的编号自然会出现 |
| 识别报告 | 源文件、PDF 类型、页数、参数表数、型号数、参数行数（保留后）、**保留分节**、**分节明细（每节多少行 / 保留或丢弃）**、**丢弃行数**、数据行数、脚注数、未识别页、识别方式、生成时间、AI 标识 |

格式约定：表头深蓝 `#1F3864` 白字；分节 `#D9E2F3`；边框 `#BFBFBF`；**数值按原字符串小数位设格式**（`10.0`→`0.0`、`1.18E-03`→`0.00E+00`），文本单元格用 `@`；超 15 位或带前导零的数字按文本保留。

## 8. 前端

「电机库 → 导入电机参数 → 通道 2」打开弹窗，两步：

1. **上传**：拖拽/选择一个 PDF；下方折叠显示历史任务（查看 / 下载 / 删除）。
2. **结果**：结论横幅（READY/EMPTY）+ 统计九宫格 + 「下载 Excel」+ 左下角「再次上传 PDF」（直接选文件即转换，不退回上传页）+ 右侧「删除任务」；关闭用右上角 ×。

**返回与再次上传是两件事，各只有一个入口**：
- **返回上一步** = 点击步骤条第 1 步（结果页该步标题渲染成 `← 上传样册 PDF` 链接样式：主色 + 虚线下划线，hover 转实线）。不另设「返回」按钮——返回到上传页不会撤销任何东西（任务与 Excel 已在服务端生成），多一个按钮只会造成「点了能反悔」的错觉。
- **再次上传** = 左下角按钮，直接弹文件选择并以新任务替换当前结果，省掉「退回上传页 → 再选 → 再点上传」两步。
- 「删除任务」用危险色描边置于右侧，与上述两类操作分出主次。弹窗底部不再放「关闭」按钮（右上角 × 已足够）。

## 9. 已知边界

| 场景 | 行为 |
|---|---|
| 扫描件 / 纯图片 PDF | 无可提取文字 → `EMPTY`，提示改用带文字层 PDF（不做 OCR） |
| 无「符号 + 单位」表头的表格 | 不识别（宁可漏，不猜） |
| 型号 > 12 个 | 只出参数汇总，不出每型号页（避免上百个可分页） |
| 页面旋转 ≠ 0 | 未处理旋转页（样册通常为 0/180；如有需要按 `PDPage.getRotation()` 校正） |
| 相邻单元格间距 < 1.7pt | 可能并成一格（几何切分的固有极限，脚本版靠 PDF 文本对象边界更稳） |
